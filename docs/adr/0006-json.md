# ADR-0006: JSON: ordered values, serde_json-exact text

- **Status:** Accepted (2026-10-21, with the plan)
- **Plan decision:** D6

## Context

Every body teta-wot sends is written by serde_json 1.0.151 with `preserve_order`. Drogon's jsoncpp sorts object keys. nlohmann's `dump()` escapes strings as serde_json does, but lays out numbers differently: measured against the corpus below, 469 of 7,520 doubles differ (`1e-07` for `1e-7`, `1e+15` for `1000000000000000.0`, `9.007199254740992e+15` for `9007199254740992.0`).

## Decision

- **Values are `nlohmann::ordered_json`** (`teta::wot::json::Value`): insertion order, and integers and floats kept apart, as pydantic emulation needs.
- **Text is written by our own serialiser** (`teta::wot::json::dump`, `dump_pretty`), which reproduces serde_json 1.0.151:
  - floats in shortest round-trip form, as decimals when the decimal exponent is in [-5, 15] (`1.0`, `0.00001`, `1000000000000000.0`), otherwise in scientific notation with a signed exponent (`1e+16`, `1e-7`, `1.7976931348623157e+308`), `-0.0` kept;
  - strings with only `"`, `\`, `\b`, `\f`, `\n`, `\r`, `\t` and other control characters (`\u00XX`, lowercase) escaped, UTF-8 otherwise;
  - `dump_pretty` as serde_json's `PrettyFormatter` with a four-space indent (settings files).
- **The specification is a corpus written by serde_json itself** (`tests/json/serde_json_corpus.txt`, from `conformance/reference-rs`'s `json-corpus`: 7,600+ doubles, integers, strings and indented documents). CI regenerates it and fails if it changes.
- jsoncpp is never used on the wire.

## Consequences

- Parsing details (duplicate keys, `-0`, numbers beyond 64 bits) are settled in Phase 1 against the reference.
